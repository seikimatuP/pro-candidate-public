## 設定管理の基本原則

当プロジェクトでは以下の原則に従って設定を管理します：

1. **コードと設定の分離**：アプリケーションロジックと設定値は明確に分離する
2. **環境毎の適切な設定**：開発・テスト・本番など環境ごとに適切な設定値を使用する
3. **最小権限の原則**：設定変更には必要最小限の権限のみを与える
4. **バージョン管理**：設定変更の履歴を記録し、過去の状態に戻せるようにする
5. **監査性**：誰がいつどのような設定変更を行ったかを追跡可能にする

## 設定キーの命名規則

設定キーは以下の命名規則に従ってください：

1. **大文字のスネークケース**を使用（例：`DATABASE_HOST`）
2. **カテゴリのプレフィックス**を付ける（例：`DB_HOST`, `API_KEY`）
3. **一貫性**のある命名パターンを維持する
