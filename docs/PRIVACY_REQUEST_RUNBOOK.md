# 個人情報に関する請求対応ランブック

最終更新日: 2026年8月22日

## 目的

本人または法定代理人からの開示・訂正・利用停止・削除請求を、安全かつ一貫して処理し、再収集を防止する。公開窓口は `frontend/public/privacy.html`、除外リストの技術手順は `SCRAPING_POLICY.md` を参照する。

## 役割と期限

- 受付責任者: 運営者
- 受付確認: 原則2営業日以内
- 完了目標: 受付から原則2週間以内
- 緊急非表示: なりすましのおそれより本人の権利侵害が大きいと判断した場合は、確認完了前でも一時的に API 配信対象から外す
- 二者確認ができない個人運営時は、実施時と翌日に同じチェックリストを再確認する

## 受付記録（必要最小限）

受付台帳には次だけを記録する。本人確認書類の写し、メール本文全文、不要な家族情報は保存しない。

| 項目             | 内容                         |
| ---------------- | ---------------------------- |
| request_id       | `PRIV-YYYYMMDD-連番`         |
| 受付日時         | JST                          |
| 請求区分         | 開示・訂正・利用停止・削除   |
| 対象             | 氏名、学校、年度             |
| 請求者区分       | 本人・法定代理人             |
| 確認方法         | 公示情報との照合、返信確認等 |
| 暫定措置         | 実施有無と日時               |
| 対応内容         | S3更新、除外登録等           |
| 完了日時         | JST                          |
| 本人への回答日時 | JST                          |
| 再確認日時       | 翌日または次回収集後         |

## 対応手順

1. 受付メールへ request_id を付け、請求区分と対象を確認する。
2. 氏名、学校、年度を公示・保有データと照合する。追加情報が必要な場合も最小限にする。
3. 法定代理人の場合は、本人との関係と代理権を合理的な方法で確認する。判断が難しい場合は、情報を追加取得する前に専門家へ相談する。
4. 緊急性を評価し、必要なら除外リストへ暫定登録して API 配信を止める。
5. 対象年度の保存データを訂正・削除し、削除・利用停止の場合は `config/exclusion-list.json` へ登録する。
6. 公開 `/statistics`、admin 一覧、氏名検索、学校別選手、スクレイピング履歴・通知に対象が残っていないことを確認する。
7. API の除外キャッシュが切れる5分後に再確認する。
8. 請求者へ結果、対応日、対応できない範囲を回答する。
9. 次回スクレイピング後に再収集されていないことを確認し、受付台帳を完了にする。

## 失敗時

- 除外リストが読めない場合は、スクレイピング保存と個人データ API が fail closed になっていることを確認する。
- 誤削除・誤訂正が疑われる場合、個人データ API を停止し、S3 バージョンから影響範囲を調査する。復元は請求内容と本人への説明を確認してから行う。
- 漏えい等が疑われる場合は `docs/EMERGENCY.md` に従い、個人情報保護委員会への報告・本人通知の要否を専門家と確認する。

## 定期テスト

- 四半期ごと: 架空データで「受付 → 暫定非表示 → 除外登録 → 次回収集後の再確認」を通し実施する。
- 年1回: 年度別データ、除外リスト、アクセスログ、スクレイピング履歴、バックアップの保持必要性を見直す。
- 記録するもの: 実施日、担当者、対象環境、結果、失敗箇所、是正日。実在人物の情報をテストに使わない。

## 保存期間

- 受付台帳: 対応完了後3年を目安に、法的必要性を年1回見直す。
- 本人確認のために一時取得した追加情報: 確認完了後、不要になり次第削除する。
- 除外リスト: 再収集防止に必要な間保持する。氏名・学校・理由・追加日時以外を保存しない。
- 過年度の選手データ: 統計目的の必要性を年1回評価し、不要な年度は S3 の現行版・旧版・キャッシュを含めて削除する。
