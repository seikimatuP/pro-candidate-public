## 実施内容

### 1. メール通知失敗の原因調査と解決

#### 問題の詳細

- **症状**: prod環境での定期実行時にメール通知が送信されない
- **エラー**: Lambda実行時に環境変数 `ENABLE_EMAIL_NOTIFICATION` と `S3_DATA_BUCKET` が未設定
- **影響範囲**: prod/dev両環境のスクレイピングLambda関数

#### 根本原因

昨日（9/17）のCDKデプロイ（v1.3.7）時に、CDKコードに環境変数が定義されていなかったため、デプロイのたびに環境変数がリセットされていた。

手動で設定した環境変数が、CDKデプロイによって上書きされてしまう仕様のため。

#### 解決策

1. **一時対応（完了済み）**

   - AWS CLIで手動環境変数追加
   - prod: `ENABLE_EMAIL_NOTIFICATION=true`, `S3_DATA_BUCKET=pro-candidate-data-prod`
   - dev: `ENABLE_EMAIL_NOTIFICATION=true`, `S3_DATA_BUCKET=pro-candidate-data-dev`

2. **恒久対応（実施済み）**
   - `pro-candidate-aws/lib/constructs/lambda-construct.ts` の修正
   - スクレイピングLambda関数の環境変数定義に `S3_DATA_BUCKET: props.dataBucket.bucketName` を追加
   - これによりCDKデプロイ時に環境変数が自動設定され、リセットされない

### 2. CDK Lambda Construct修正

#### 修正内容

```typescript
// pro-candidate-aws/lib/constructs/lambda-construct.ts
environment: {
  ...props.environment,
  ENABLE_EMAIL_NOTIFICATION: 'true',
  NOTIFICATION_EMAIL: 'yuta.nozue@gmail.com',
  SENDER_EMAIL: 'yuta.nozue@gmail.com',
  EMAIL_TO: 'yuta.nozue@gmail.com',
  EMAIL_FROM: 'yuta.nozue@gmail.com',
  S3_DATA_BUCKET: props.dataBucket.bucketName, // ← 追加
},
```

#### 修正の効果

- CDKデプロイ時に環境変数が自動的に設定される
- Infrastructure as Codeの原則に従い、設定が永続化される
- 手動設定の必要がなくなり、運用負荷が軽減

## 追加作業: prod環境Lambda IAM権限エラーの調査と修正

### 問題の発見

**エラー内容**

- prod環境の定期実行でメール通知が「失敗」として届いた
- CloudWatch Logsで多数のAccessDeniedエラーを確認
- 影響範囲：`cache/*`、`previous-counts/*`ディレクトリへのアクセス

### 根本原因

**CDKコードのIAMポリシー定義漏れ**

Lambda関数に新機能（前回実行との差分計算）を追加した際：

1. Lambda関数のコードは更新した
2. しかし、CDKの`lambda-construct.ts`のIAMポリシー定義を更新し忘れた
3. 本日のCDKデプロイ（v1.3.8）で不完全な権限が適用された

**不足していたS3パス権限**：

- `cache/scraping-status.json` - スクレイピングステータス保存用
- `previous-counts/*.json` - 前回実行との差分計算用

### 実施した対応

#### 1. 緊急対応（手動修正）

AWS CLIでIAMポリシーを直接修正：

```bash
# S3Accessポリシーに以下のパスを追加
"arn:aws:s3:::pro-candidate-data-prod/cache/*"
"arn:aws:s3:::pro-candidate-data-prod/previous-counts/*"
```

結果：Lambda関数が正常に実行できることを確認

#### 2. 恒久対応（CDKコード修正）

`pro-candidate-aws/lib/constructs/lambda-construct.ts`を修正：

```typescript
// S3アクセス権限に追加
resources: [
  `${props.dataBucket.bucketArn}/players/*`,
  `${props.dataBucket.bucketArn}/config/*`,
  `${props.dataBucket.bucketArn}/scraping-history/*`,
  `${props.dataBucket.bucketArn}/cache/*`, // スクレイピングステータス用
  `${props.dataBucket.bucketArn}/previous-counts/*`, // 前回実行との差分計算用
],

// ListBucket権限のプレフィックスにも追加
's3:prefix': [
  'players/*',
  'config/*',
  'scraping-history/*',
  'cache/*', // スクレイピングステータス用
  'previous-counts/*', // 前回実行との差分計算用
],
```

#### 3. 再デプロイ実施

- prod環境へのCDKデプロイ完了（21:09 JST）
- ConfigurationSet設定も同時に反映
- Lambda関数の正常動作を確認
