### 5. SPA RoutingRules設定問題の再発見と修正

**時刻**: 04:35 - 05:30

**E2Eテスト実行結果**:

```
❌ Authentication failed: page.waitForSelector: Timeout 30000ms exceeded.
📄 Page HTML (first 1000 chars): <!DOCTYPE html>...
📋 Body text (first 500 chars): [空白]
コンソールエラー: "No routes matched location "/index.html""
```

**問題の再調査**:

```bash
curl -I "http://pro-candidate-frontend-dev.s3-website-ap-northeast-1.amazonaws.com/dashboard"
# HTTP/1.1 301 Moved Permanently
# Location: http://pro-candidate-frontend-dev.s3-website-ap-northeast-1.amazonaws.com/index.html
```

**根本原因特定**:

- **RoutingRulesは301リダイレクトを生成**
- URLが`/dashboard` → `/index.html`に書き換わる
- React Routerが`/index.html`というパスを認識できない
- `No routes matched location "/index.html"`エラー発生

**正しいSPA設定の理解**:

- S3 Website Hostingでは`websiteErrorDocument`のみ使用
- 404エラー時に`index.html`の**内容**を返す（URLは保持）
- RoutingRulesは不要（むしろ有害）

**実施した修正**:

```typescript
// RoutingRulesを完全削除
// websiteIndexDocument + websiteErrorDocumentのみでSPA対応
this.bucket = new s3.Bucket(this, 'FrontendBucket', {
  websiteIndexDocument: 'index.html',
  websiteErrorDocument: 'index.html', // これだけでOK
  // RoutingRulesは不要
});
```

**コミット**: `fix: S3 RoutingRules削除・websiteErrorDocumentのみでSPA対応`

**技術的詳細**:

- `websiteErrorDocument`は404エラー時にindex.htmlの内容を返す
- HTTPステータスは404のまま、コンテンツのみ差し替え
- ブラウザのURLは変更されない → React Routerが正常動作

### 9. prod環境E2Eテスト実行・タイムアウト問題発見

**時刻**: 17:45 - 18:00

**実施内容**:

```bash
scripts/run-e2e-test.sh prod
```

**結果**:

```
❌ Authentication failed: page.waitForTimeout: Test timeout of 30000ms exceeded.
    at tests/e2e/auth.setup.ts:241:16
```

**原因分析**:

`playwright.config.ts` 76-81行:

```typescript
// dev環境のみタイムアウト延長が適用されていた
actionTimeout: getEnvironment() === 'dev' ? 180000 : 30000,      // dev: 3分
navigationTimeout: getEnvironment() === 'dev' ? 300000 : 60000,  // dev: 5分
timeout: getEnvironment() === 'dev' ? 240000 : 30000,  // dev: 4分
```

**問題点**:

- prod環境は30秒タイムアウトのまま
- dev環境のみ180-300秒の延長設定
- prod環境でもネットワーク遅延があるため同様の延長が必要

---

### 10. v1.4.2ホットフィックス・prod環境タイムアウト延長

**時刻**: 18:00 - 18:15

**実施した修正**:

`playwright.config.ts` 76-81行:

```typescript
// dev/prod両環境にタイムアウト延長を適用
actionTimeout: getEnvironment() !== 'local' ? 180000 : 30000,      // dev/prod: 3分（遅延対応）
navigationTimeout: getEnvironment() !== 'local' ? 300000 : 60000,  // dev/prod: 5分（初回接続対応）
timeout: getEnvironment() !== 'local' ? 240000 : 30000,  // dev/prod: 4分（全体テストタイムアウト）
```

**コミット**: `fix: prod環境E2Eテストタイムアウト延長・認証セットアップ堅牢化`

**変更内容**:

- 条件式変更: `getEnvironment() === 'dev'` → `getEnvironment() !== 'local'`
- local環境のみ30秒タイムアウト維持
- dev/prod環境は同一の延長タイムアウト設定

**理由**:

- prod環境でもCloudFront経由の初回接続に時間がかかる
- ネットワーク遅延は環境問わず発生する可能性がある
- 認証セットアップには十分な時間が必要
