await page.evaluate(async () => {
  // Service Workerをクリア（最優先）
  if ('serviceWorker' in navigator) {
    const registrations = await navigator.serviceWorker.getRegistrations();
    for (const registration of registrations) {

## 🔍 技術的詳細・学び

### Service Workerキャッシュ問題

**Service Workerとは**:

- ブラウザとネットワークの間に位置するプロキシ
- オフライン動作・プッシュ通知・バックグラウンド同期を実現
- **キャッシュAPIを使用してリソースを保存**
- PWA（Progressive Web Apps）の中核技術

**キャッシュ優先順位**:

1. **Service Workerキャッシュ** - 最優先（ネットワークリクエスト前にインターセプト）
2. ブラウザHTTPキャッシュ - Cache-Controlヘッダーに従う
3. CloudFrontキャッシュ - CDNレベルのキャッシュ

**問題の構造**:

- CloudFrontキャッシュ無効化 → ✅ 成功
- ブラウザHTTPキャッシュ → ⚠️ Cache-Controlで制御可能
- **Service Workerキャッシュ** → ❌ 明示的削除が必要（今回の問題）

### Playwright Service Workerブロック

**serviceWorkers: 'block'の効果**:

- 新しいService Worker登録をブロック
- 既存のService Workerの実行をブロック
- テスト実行中のService Worker干渉を防止

**bypassCSP: trueの効果**:

- Content Security Policy（CSP）ヘッダーを無視
- Service Workerのセキュリティ制約をバイパス
- テスト環境での柔軟な実行を可能に

### ブラウザキャッシュ無効化オプション

**Chromiumオプション**:

- `--disable-cache`: HTTPキャッシュ完全無効化
- `--disk-cache-size=0`: ディスクキャッシュサイズを0に設定
- `--disable-application-cache`: Application Cache（古いHTML5機能）無効化

**効果**:

- テスト実行ごとに常に最新リソースを取得
- キャッシュ関連の不具合を排除
- テスト結果の一貫性確保

### ESLint globals設定

**問題**:

```
error: 'caches' is not defined (no-undef)
```

**解決**:

```typescript
/* global localStorage, sessionStorage, caches */
```

**理由**:

- `caches`はブラウザグローバルAPI（Service Worker Caches API）
- ESLintはブラウザグローバルを認識しないため、明示的宣言が必要
- `localStorage`・`sessionStorage`と同様の扱い
