### 5. dev環境のCORSエラー修正

#### 問題

- dev環境でAPIリクエスト時にCORSエラーが発生
- エラー: "Request header field pragma is not allowed by Access-Control-Allow-Headers"

#### 原因

- フロントエンドから送信している`Pragma: no-cache`ヘッダーがAPI GatewayのCORS許可リストにない
- `Pragma`と`Expires`はHTTP/1.0の古いヘッダーで、現代のブラウザでは不要

#### 解決策（Geminiの提案）

- フロントエンドから`Pragma`と`Expires`ヘッダーを削除
- `Cache-Control`ヘッダーのみでキャッシュ制御を実現
- `frontend/src/services/api.ts`を修正してヘッダーを削除

#### 確認事項

- API GatewayのCORS設定で`Cache-Control`は許可リストに含まれている
- `Pragma`と`Expires`は許可リストに含まれていない（これが正しい設定）

### 7. 管理者権限設定とトークンリフレッシュ問題の解決

#### 問題

- AWS Cognitoでadminユーザーをadminグループに追加後、管理者機能が表示されない
- 再ログインしても権限が反映されない

#### 原因

- `getCurrentUser()`ではグループ情報が取得できない
- トークンが古いままでグループ情報が更新されていない

#### 解決方法

##### AWS CLIでグループ追加

```bash
aws cognito-idp admin-add-user-to-group \
  --user-pool-id ap-northeast-1_yRTv0CRfz \
  --username admin \
  --group-name admin \
  --region ap-northeast-1
```

##### AuthContext.tsx修正

```typescript
import { fetchAuthSession } from 'aws-amplify/auth';

const getUserGroups = async (): Promise<string[]> => {
  // 初回のみ強制更新
  const forceRefresh = !user?.groups;
  const { tokens } = await fetchAuthSession({ forceRefresh });
  const groups = tokens?.idToken?.payload?.['cognito:groups'];

  if (Array.isArray(groups)) {
    return groups.filter((g): g is string => typeof g === 'string');
  }
  return [];
};
```
