## 実施内容

### 1. AWS SSO認証への移行

#### 背景
- セキュリティ向上のため、IAMアクセスキーの使用を廃止
- AWS SSO (IAM Identity Center)による一元管理に移行

#### 移行内容

1. **IAMアクセスキー廃止**
   - 従来のアクセスキー/シークレットキー認証を無効化
   - ~/.aws/credentialsからアクセスキー情報を削除

2. **SSO設定**
   ```
   Profile: yn-account-AdministratorAccess-131492497870
   SSO Start URL: https://d-9567a02726.awsapps.com/start
   Region: ap-northeast-1
   Account ID: 131492497870
   Role: yn-account-AdministratorAccess
   ```

3. **認証方法の変更**
   - 旧: `aws configure`でアクセスキー設定
   - 新: `aws sso login --profile yn-account-AdministratorAccess-131492497870`

## AWS認証設定

### SSO認証の使用（IAMアクセスキーから変更済み）

- **認証方法**: AWS SSO (IAM Identity Center)を使用
- **IAMアクセスキー**: 使用禁止（セキュリティ向上のため）

- **認証期限**: SSOセッション有効期限に従う

### 4. セキュリティ向上効果

#### SSO移行のメリット

1. **アクセスキー漏洩リスクの排除**
   - 永続的な認証情報をローカルに保存しない
   - gitへの誤コミット防止

2. **一時的認証トークンの使用**
   - セッション有効期限による自動無効化
   - 定期的な再認証要求

3. **中央管理**
   - IAM Identity Centerでの一元管理
   - ロール切り替えの簡易化
   - 監査ログの充実

4. **MFA対応**
   - 多要素認証の強制が可能
   - より強固なセキュリティ体制

## 技術的な注意点

### SSO使用時の注意事項

1. **セッション管理**
   - 定期的に`aws sso login`が必要
   - セッション有効期限切れ時は再認証

2. **プロファイル指定**
   - コマンド実行時に`--profile`フラグ必須
   - 例: `aws s3 ls --profile yn-account-AdministratorAccess-131492497870`

3. **CI/CD環境**
   - GitHub ActionsはIAMロールベースの認証を継続使用
   - ローカル開発環境のみSSO使用
